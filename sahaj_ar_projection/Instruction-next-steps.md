### Step 44: base-line (contact-line) depth reference with a gated threshold (offline, GPU)
- [ ] Goal: test Sahaj's idea (25 Oct). The panel's base edge lies on the table, so its extension across the image is a line of known geometry between foreground and background. Use the model depth along that line as a local reference, and call a pixel an occluder only when the model reads it clearly nearer than the reference. A bias shared by the line and the panel then cancels, and false occlusions are gated by the threshold.
- Geometry: the line is the intersection of the panel plane with the table plane (world), extended beyond the panel, projected with the tracker pose. Sample it only where it lies inside the image. Its true depth varies along the line when the camera is oblique, so take the expected depth profile `Z_line(u)` from the pose (ray-plane) and compare it with the model along the line; do not average to one number unless the profile is nearly constant.
- Method (one change per run; default off):
  1. Reference from the line: fit a shift (and, only if the profile spans enough depth, a scale) between model depth and `Z_line` along the clean part of the line. Take scale from the held tag-plane scale (Step 30) otherwise. Because the test compares a pixel with the line, a common additive bias cancels and a scale error only multiplies a small difference.
  2. Robust statistic: occluders can only make the line read nearer, never farther. Use an upper percentile of the line depth ratio (start at the 70th percentile of depth, i.e. the farther side), or the median of the farther half. Report the line spread after the fit (MAD) as the local noise.
  3. Mask rule: a pixel in the panel region is an occluder when `Z_model_aligned < Z_panel - margin`. Margins: fixed 0.15 m and 0.20 m, 10% of depth, and an adaptive margin of 4 x the line MAD (floor 0.05 m). Compare all four.
  4. Gate: require a minimum fraction of the line inside the image and clean (for example 30% of its length, at least 40 px), line MAD below a limit, and a held value from a recent good frame when a hand or object covers the line. If the gate fails, hold the last good reference for up to a set time, then show the panel unoccluded and log "visibility unavailable". Never reuse a stale mask.
  5. Run the same procedure with both depth models: the Hypersim metric model and the relative model aligned in disparity (Step 43). The test is the same for both.
- Known limits to report, not hide:
  - An object or the hand covering the line contaminates the reference. The upper-percentile rule and the hold reduce this; report how often the gate fails and why.
  - A hand that the model reads as far (V2/441 with the metric model) is still a miss: this method removes common bias, it does not fix a depth blind spot. Expect the relative model to be the one that can fix it. Record both.
  - A false nearer blob larger than the margin (halo at an edge, flat-region gradient) still passes the gate. The line only removes common-mode bias.
  - The bias gradient inside the panel region (rows above the base line) is not corrected. Report the residual bias by row inside the panel.
  - The line may fall outside the image (panel near the image border); report how often.
- Evaluation: Step 36 frame set (V3/26 and 20-30, V4/1270-1280, V0 worst and random, V2/441 window, V2/72, controls), F-empty and F-occ, and the Step 41 labels when they exist. Report false-hide fraction, miss rate on labelled front occluders, gate pass fraction, line MAD per distance band, and hidden fraction against panel depth. Compare with the Step 42 margins on the anchor fit, with identical frames.
- Pass criteria (set in advance): F-empty mean hidden at most 2% at margin 0.15 m or adaptive, V0 mean at most 1%, and no worse miss rate than the anchor fit on labelled frames.
- Output: `scripts/step44_baseline.py`, `runs/step44-baseline.json` and `.md`, images for the worst frames as in Step 42, section 6 and section 7 entries. Default off; no change to production defaults.
- Hardware: GPU only. No camera.
